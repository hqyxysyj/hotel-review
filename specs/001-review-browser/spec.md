# Feature Specification: 花园酒店评论浏览

**Feature Branch**: `001-review-dashboard`  
**Created**: 2026-04-13  
**Status**: Draft  
**Input**: User description: "基于 public/enriched_comments.csv 花园酒店住客评论数据集，搭建一个评论浏览网页，要能按条件筛选、关键词搜索、可以查看图片，并且网页要美观。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 快速定位目标评论 (Priority: P1)

作为运营或服务改进人员，我希望能按评论条件快速筛选并浏览评论列表，以便高效找到需要关注的住客反馈。

**Why this priority**: 评论筛选与浏览是核心价值，若无法高效定位评论，后续搜索与图片查看价值会明显下降。

**Independent Test**: 仅实现该故事时，用户可通过条件筛选看到符合条件的评论并完成基础浏览，已可支持最小可用分析场景。

**Acceptance Scenarios**:

1. **Given** 用户进入评论浏览页且数据已加载，**When** 用户选择评分区间和入住时间范围，**Then** 页面仅展示满足条件的评论结果。
2. **Given** 当前已设置多个筛选条件，**When** 用户点击重置筛选，**Then** 页面恢复展示完整评论列表并清空筛选状态。

---

### User Story 2 - 关键词检索评论内容 (Priority: P2)

作为运营或服务改进人员，我希望通过关键词搜索评论文本，以便快速查找与特定主题（如卫生、早餐、服务态度）相关的反馈。

**Why this priority**: 关键词搜索是高频分析动作，可显著缩短人工翻阅时间，但在无筛选能力时仍可部分使用，因此优先级次于 P1。

**Independent Test**: 仅实现该故事时，用户可输入关键词并获得匹配评论，能独立完成主题性反馈检索。

**Acceptance Scenarios**:

1. **Given** 评论列表已展示，**When** 用户输入关键词并执行搜索，**Then** 页面只展示评论文本中包含该关键词的记录。
2. **Given** 用户已执行关键词搜索，**When** 用户清空关键词，**Then** 页面恢复为当前筛选条件下的完整评论结果。

---

### User Story 3 - 查看评论关联图片 (Priority: P3)

作为运营或服务改进人员，我希望在浏览评论时查看评论关联图片，以便更直观理解住客反馈场景和问题细节。

**Why this priority**: 图片查看增强分析深度与准确性，但不影响纯文本评论的基础可用性，因此优先级低于筛选和搜索。

**Independent Test**: 仅实现该故事时，用户可在评论项中打开并查看图片，能够独立完成图文联合核查。

**Acceptance Scenarios**:

1. **Given** 某条评论包含图片，**When** 用户点击图片缩略图，**Then** 页面展示可清晰查看的大图。
2. **Given** 用户正在查看大图，**When** 用户关闭图片查看层，**Then** 页面返回原评论浏览位置且不丢失当前筛选与搜索状态。

---

### Edge Cases

- 当筛选与关键词同时生效且无匹配结果时，页面应明确提示“无匹配评论”，并提供快速清空条件入口。
- 当评论记录缺失图片或图片链接失效时，页面应展示不可用提示，不应影响其他评论浏览。
- 当关键词仅为空格、特殊符号或超长输入时，系统应按可理解规则处理并给出一致反馈。
- 当数据集中存在异常字段值（如评分为空、日期格式异常）时，页面应忽略异常记录或提供降级展示，不导致整体不可用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 从 `public/enriched_comments.csv` 数据集中读取并展示评论列表。
- **FR-002**: 系统 MUST 提供至少以下可组合筛选能力：评分、评论日期或入住时间、是否含图。
- **FR-003**: 用户 MUST 能通过关键词搜索评论文本内容，并即时获得匹配结果。
- **FR-004**: 系统 MUST 在筛选与搜索同时生效时展示其交集结果，并可一键清空所有条件。
- **FR-005**: 用户 MUST 能查看评论关联图片的放大视图，并可返回原列表位置继续浏览。
- **FR-006**: 系统 MUST 在无结果、数据缺失、图片不可用等场景下提供清晰可理解的状态反馈。
- **FR-007**: 系统 MUST 提供分页或分段加载能力，确保大批量评论下仍可持续浏览。
- **FR-008**: 页面 MUST 采用统一视觉风格，具备清晰信息层级与良好可读性，满足“美观”目标。

### Key Entities *(include if feature involves data)*

- **评论记录 (Review)**: 表示一条住客评论，核心属性包括评论文本、评分、评论时间、来源渠道、是否含图。
- **筛选条件 (Filter Set)**: 表示用户当前选择的一组过滤参数，包括评分范围、时间范围、是否含图等。
- **搜索条件 (Search Query)**: 表示用户输入的关键词及其匹配规则。
- **评论图片 (Review Image)**: 表示与评论关联的图片资源，包含缩略显示与大图查看两个展示状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% 的目标用户可在 30 秒内完成“设置条件并找到目标评论”的任务。
- **SC-002**: 在常规数据量下，95% 的筛选或关键词搜索操作在 2 秒内呈现结果变化。
- **SC-003**: 至少 95% 的含图评论可成功完成“缩略图打开-查看大图-关闭返回”完整流程。
- **SC-004**: 可用性测试中，至少 85% 的参与者对页面视觉体验给出“清晰、舒适、易读”的正向评价。

## Assumptions

- 数据文件 `public/enriched_comments.csv` 已可在运行环境中稳定访问，且字段命名整体可用于评论展示。
- 当前版本面向桌面端主流浏览器，移动端深度适配不作为本次范围内的强制目标。
- 页面主要服务于中文阅读场景，默认中文界面与中文关键词检索。
- 本功能聚焦“浏览与分析”而非“编辑与运营处理”，不包含评论修改、删除、回复等操作。
